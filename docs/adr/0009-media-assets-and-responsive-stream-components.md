# 采用多媒体资产协同管理与响应式流媒体短代码组件

为了提升技术文档中架构插图、录屏演示与流媒体视频的排版质感与开发体验，消除原生 HTML 标签的生硬感与移动端黑边问题，我们决定规范多媒体管理体系并提供开箱即用的短代码组件。

## 考虑备选

- **仅依赖 Markdown 原生语法与裸写 HTML5 标签**：
  - 图片使用 `![alt](url)`，视频直接写 `<video src="..." controls>`，B站/YouTube 裸写 `<iframe>`；
  - 缺陷：原生 Markdown 没有视频语法；原生 `<video>` 缺少现代阴影、圆角与深浅色模式边框；第三方 `<iframe>` 高度固定，在移动端窄屏下产生大面积黑边且无法自适应 16:9。
- **引入外部大型视频播放器库（如 Video.js 或 DPlayer）**：
  - 缺陷：带来数十 KB 的运行时打包负担与复杂的 CSS 污染，与 VitePress 轻量极速的哲学相违背。
- **现代轻量短代码组件 + 全局响应式 CSS 保底（采纳）**：
  - **原生语法全面兼容**：标准 Markdown 图片语法自动由 Vite 打包哈希，并默认享受 `mediumZoom` 平滑全屏放大灯箱；
  - **纯 CSS 双模图片自适应**：提供 `.light-only` 与 `.dark-only` 类名，实现零 JS 运行时的深浅色无闪烁平滑交替；
  - **开箱即用免 import 短代码**：
    - `<VpImage>`：单行实现双模图切换、自定义宽度与居中图注；
    - `<VpVideo>`：优雅包裹本地/网络 MP4，带现代圆角、加载海报、宽高比锁定与网络离线断网优雅兜底；
    - `<VpBilibili>`：只需 BV 号，自动输出 16:9 响应式容器，默认关闭弹幕防打扰，内置加载微光骨架屏与 PWA 离线降级卡片；
    - `<VpYouTube>`：采用 `youtube-nocookie.com` 增强隐私域名，自适应全屏并提供断网离线友好降级。

## 产生的后果

- 文档作者既可沿用标准 Markdown 图片写法，也能在需要视频与双模图时极简调用短代码组件；
- 移动端与桌面端全尺寸下视频均维持 16:9 黄金宽高比，彻底消除页面重排抖动与黑边；
- 契合 PWA 离线就绪哲学，在断网弱网状态下提供清晰兜底与原站直链，杜绝原生浏览器白屏；
- 在 `docs/guide/media-assets.md` 与 `docs/components/overview.md` 中建立了完整的实机交互演示 (Live Demo) 与大文件防爆仓规范。
